微信小程序接入阿里云 OSS 对象存储：跑腿小程序里哪些功能用到了它

  • 微信小程序 
  • | 阿里云 
  • | OSS 
  • | 对象存储 
 

我们有一个校园跑腿类的微信小程序（小程序 + 管理后台 + Midway 后端）。上线前梳理外部依赖时，我把代码里所有用到阿里云 OSS 的地方过了一遍。这篇先讲项目里哪些功能会用到 OSS，再讲怎么配，最后讲一个我在代码里发现的问题：为什么最好准备两个 Bucket。

一、项目里哪些功能会用到 OSS

小程序端：用户上传的图片

小程序里所有上传都走同一个 upload() 方法：先传到我们自己的后端 /api/upload/put，由后端用 ali-oss 的 SDK 写进 OSS，返回 https 地址。文件名是随机的 20 位 ID，前缀由请求头决定，默认是 pic/。

功能 页面 / 组件 前缀
发布跑腿订单时添加图片、备注图 发布页、跑腿描述组件 errands/
发布打印订单时上传要打印的文件图片 发布页 print/
订单附件（最多 3 张） 服务下单的附件组件 pic/
修改头像、服务头像 个人资料页、头像组件 pic/
接单员认证：上传学生证 接单员注册页 pic/
接单员认证：上传身份证（国徽面、人像面） 接单员注册页 pic/
接单员操作订单时拍照上传 订单接单操作组件 pic/

管理后台：浏览器直传和图片展示

  • 素材管理和通用上传组件：后台的素材图片页，以及后台录入接单员时上传学生证等，都是浏览器直传 OSS，用后端 /admin/sts 换来的临时凭证，不经过我们的服务器。
  • 缩略图：后台里的头像、订单图、素材图都通过 OSS 的图片处理参数（x-oss-process=image/…/resize）按需裁剪，不用自己做缩略图。
  • 微信支付证书：后台「商户配置」里，要上传微信支付的 apiclient_cert.p12、apiclient_cert.pem、apiclient_key.pem，用的也是这个直传方法，文件路径是 cert/。后端要退款时，会按保存的地址把这三个文件下载下来使用。

所以这个项目一共有三类东西放在 OSS 里：用户上传的订单图和头像、接单员的证件照、微信支付证书。

二、为什么要两个 Bucket

看完上面这张表会发现问题：目前代码里只有一个 ossBucket 配置，所有文件都写进同一个 Bucket。

而为了让小程序里的 <image> 能直接用裸链接显示图片（代码里没有做签名 URL），这个 Bucket 必须是公共读。结果是：

  • 接单员的身份证照片、学生证，任何人拿到链接就能看；
  • 微信支付的 API 证书和私钥（apiclient_key.pem）也放在 cert/ 下，同样是公共读。文件名虽然是随机 UUID，但「靠猜不到」不是权限控制，链接一旦出现在日志、截图或数据库导出里，私钥就泄露了。

所以正确的做法是分成两个：

Bucket 读写权限 放什么
图片桶 公共读 订单图、头像、素材、富文本图片
敏感文件桶 私有 身份证、学生证、微信支付证书

需要注意：这不是只改配置就能完成的。 现状有两处代码依赖公共读：

  1. 后端下载支付证书用的是直接拿 URL 下载，私有桶会返回 403，要改成用 OSS SDK 读取，或者生成带签名的临时链接；
  2. 后台的接单员列表里，学生证是直接用图片地址显示的，换成私有桶后，要改成请求时生成签名 URL。

如果暂时不想改代码，至少要知道当前的风险，并且证书文件尽快迁移出去。

三、创建 Bucket

在 OSS 控制台 创建 Bucket，地域选离用户近的（我们用的是广州 oss-cn-guangzhou）。

图片桶（公共读） 有两层限制，两层都要改对：

  1. 创建时：读写权限只能选「私有」，这是阿里云强制的，正常现象，直接创建；
  2. 创建后，进入 Bucket →「权限管理」：
    1. 先到「阻止公共访问」，把开关关闭；
    2. 再到「读写权限」，改成公共读。

只改第二步没用，「阻止公共访问」默认开着，会照样拦截访问，图片会返回 403。

敏感文件桶（私有） 保持创建时的默认私有就行，不用动「阻止公共访问」。

另外，一个项目一个 Bucket：别和别的项目共用，不然想单独统计流量、控制权限、清理数据时容易搞混，授权范围也会被不必要地放大。新建时先看清桶名，别误点进别的项目的 Bucket。

四、RAM 子账号和 STS 角色（管理后台直传用）

浏览器直传 OSS 不能把长期密钥发给前端，要后端用 STS 换一个临时凭证（项目里是 /admin/sts 接口，后端的 STSService 调用 assumeRole）。在 RAM 控制台 里：

  1. 创建一个 RAM 子账号，生成 AccessKey，填进后台的 accessKeyId / accessKeySecret（不要用主账号的 AccessKey）；
  2. 创建一个 RAM 角色，可信实体选当前阿里云账号；
  3. 给角色添加权限 AliyunOSSFullAccess，给子账号添加权限 AliyunSTSAssumeRoleAccess；
  4. 把角色的 ARN 填进后台的 ARN 输入框。

我们踩过这个坑：ARN 一直是空的，后台上传（包括上传支付证书）就一直失败，排查了一阵才发现。

AliyunOSSFullAccess 是对所有 Bucket 的完全权限，范围比较大。想收紧的话，可以自定义一个只允许操作指定 Bucket 的权限策略，再挂给角色。

五、跨域设置（CORS）

后台直传是浏览器跨域请求，要在 OSS 里放行。进入 Bucket →「权限管理」→「跨域设置（CORS）」，添加一条规则：

项目 填写
来源 管理后台的域名，比如 https://admin.example.com
允许 Methods GET、POST、PUT、DELETE、HEAD
允许 Headers *
暴露 Headers ETag

六、小程序的域名白名单

在微信公众平台的「开发 → 开发管理 → 开发设置 → 服务器域名」里：

  • request 合法域名：填自己的 API 域名，必须是 https，而且要已经 ICP 备案（小程序上传图片走的就是它，请求的是我们自己的后端）；
  • uploadFile 合法域名：填自己的 API 域名，因为 uni.uploadFile 请求的也是后端的 /api/upload/put；
  • downloadFile 合法域名：填 OSS 域名，用于下载、预览图片。

这里要注意：小程序上传不是直传 OSS，所以 uploadFile 白名单里需要的是 API 域名。

七、配置落地

在后台的「地图及上传设置」里填：

  • ossRegion：Bucket 所在地域，比如 oss-cn-guangzhou；
  • ossBucket：桶名；
  • accessKeyId / accessKeySecret：RAM 子账号的 AccessKey；
  • arn：上面角色的 ARN。

排查清单

  • 图片返回 403：先看「阻止公共访问」是不是还开着，再看读写权限是不是公共读；
  • 后台上传失败（含支付证书）：看 ARN 是否填了，子账号是否挂了 AliyunSTSAssumeRoleAccess；
  • 浏览器控制台报跨域：检查 CORS 的来源是否和后台域名完全一致，包括 https://；
  • 小程序里上传失败：检查 request 和 uploadFile 白名单里有没有 API 域名；图片显示不出来：检查 downloadFile 里有没有 OSS 域名。

AccessKey 只放在后台配置或服务器环境里，不要写进代码、文档或聊天记录；一旦泄露，马上到 RAM 里轮换。
