阿里企业邮箱开通与 SMTP 发信完整流程

给门户页脚加了一个「留下邮箱」功能：访客留下邮箱后，后端会发一封通知邮件到我们的企业邮箱。发信用的是阿里企业邮箱的 SMTP。这个流程比想象中绕得多，这里把完整步骤记下来。

前置条件：你得先有这个邮箱

这不是随手点一下就能开通的，前提是：

  • 在阿里云买了服务器，并且用企业身份完成了备案（需要企业认证）；
  • 我是买了 .com 域名之后，阿里云赠送了企业邮箱服务，在控制台里能看到「企业邮箱-AI 尊享版」这个产品，到期时间和续费都在这里管理；
  • 我打算用 hi@jcygo.com 作为对外联系我们的邮箱账号。

注意：钉钉里的「免费试用」入口创建的是另一套临时域名邮箱，和上面这个付费产品不互通，别在那里创建。

整体思路

开通后，里面只有一个原始管理员账号（阿里官方叫 postmaster，我这边是 p…@jcygo.com）。几个要点：

  1. 新购买的企业邮箱，默认有一条「三方客户端访问策略」黑名单，不允许任何三方客户端（包括 SMTP）登录，要先关掉或把账号加进例外；
  2. 三方客户端安全密码是员工在网页邮箱里自己生成的，所以需要一个用来发信的员工账号；
  3. 我的做法是单独建一个 hi@jcygo.com，用它登录网页邮箱来生成密码，而不是用管理员账号（官方文档写的是员工自己生成，没有明说管理员账号能不能，我没有去验证管理员账号这一步）。

所以流程是：关策略 → 建一个员工账号 → 用这个账号登录 → 生成三方密码 → 填进 .env。

步骤

1. 进入域管理后台，关掉「禁止三方客户端」

用管理员账号登录域管理后台：https://mail.jcygo.com/admin/#/home

左侧菜单：安全管理 → 账号安全 → 访问策略。

你会看到一条默认的黑名单策略「禁止使用三方客户端」，把它的状态开关关掉（不关的话，SMTP 登录会被直接拒绝）。也可以不关，改成编辑策略、把 hi@jcygo.com 加进例外范围，更稳妥一些。

策略改完大约 5 分钟后才生效，别改完马上测试。

如果你的账号开了「强制启用安全密码」（后台「安全管理 → 账号安全 → 密码策略」里的开关，可以设置生效范围），那么员工只能用安全密码登录三方客户端，这也是后面第 4 步必须生成三方密码的原因。

2. 创建一个员工 / 运维账号，用来当发信账号

在后台「组织与用户」里创建一个员工账号（也可以叫运维账号），把邮箱地址设为我们要用的 hi@jcygo.com。

3. 注销管理员，改用 hi@jcygo.com 登录

这一步很关键。先把当前的管理员账号退出，然后打开网页邮箱登录页：

https://mail.jcygo.com/alimail/auth/login

用刚创建的 hi@jcygo.com 登录（首次登录会让你改密码、绑定手机等）。

4. 生成「三方客户端安全密码」

登录 hi@jcygo.com 之后，进入：

https://mail.jcygo.com/alimail/entries/v5.1/setting/account-security

也就是 设置 → 账户与安全 → 账户安全。这个页面很长，往下一直滚到最底部，找到「三方客户端登录安全管理」，在这里创建一个三方客户端密码。

我们的做法是换成 hi@jcygo.com 登录来生成。之前排查了很久，一部分原因就是没滚到页面最底部，找不到这个入口。

生成的密码只显示一次，立刻复制保存。

5. 把密码填进服务的 .env

要点：

  • 服务器 smtp.qiye.aliyun.com，端口 465（SSL）；
  • 用户名是完整的邮箱地址；
  • 密码用的是三方客户端安全密码，不是网页登录密码。

重启服务后就能发信了。

常见报错：526 Authentication failure

几乎都是下面几种原因，按顺序排查：

  1. 用了网页登录密码，而不是三方客户端安全密码；
  2. 「禁止使用三方客户端」那条访问策略没有关；
  3. 三方密码没生成成功，或者生成它的账号和 SMTP_USER 不是同一个账号。
  4. 访问策略刚改完，还没过 5 分钟。

排查工具：网页邮箱里「设置 → 日志查询 → 登录日志」，能看到每次登录的来源 IP 和成败，先确认请求到没到、是被谁拒绝的。
