小程序加管理后台的项目，涉及图片上传、文件存放的地方都可以交给阿里云 OSS。这篇不讲项目细节，只讲一件事：**业务里的每个功能，分别对应用到 OSS 的哪项能力，以及要怎么配。**

## 功能和 OSS 能力对照

| 业务功能 | 用到的 OSS 能力 | 怎么配 |
| --- | --- | --- |
| 小程序里用户上传图片 | 服务端上传：小程序把文件传给自己的后端，后端用 SDK 写进 Bucket | 后端配置 Bucket、地域和 RAM 子账号的 AccessKey；小程序域名白名单加后端域名 |
| 小程序里显示图片 | 公共读：图片用裸链接直接访问 | Bucket 设为公共读，并关闭「阻止公共访问」；`downloadFile` 白名单加 OSS 域名 |
| 管理后台上传素材、图片 | 浏览器直传：用 STS 临时凭证，文件不经过自己的服务器 | RAM 角色加 STS 权限，后端提供换凭证接口；Bucket 配 CORS |
| 后台列表里显示缩略图 | 图片处理：在链接后加 `x-oss-process` 参数，按需裁剪缩放 | 不用额外配置，不用自己生成缩略图 |
| 存放证件照、证书这类敏感文件 | 私有 Bucket：不对外公开，读取时用签名链接 | 单独建一个私有 Bucket，代码里改成签名 URL 或用 SDK 读取 |

下面按这张表，把每项能力的配置展开讲一遍。

## 一、服务端上传（小程序上传图片）

小程序里的 `uni.uploadFile` 请求的是自己的后端，由后端再用 `ali-oss` SDK 写进 OSS，返回 https 地址。文件名建议用随机 ID，再加一个前缀目录（比如 `pic/`、`order/`），方便分类和以后清理。

要配的有两处：

1. **后端**：在配置里填 `ossRegion`（Bucket 所在地域，比如 `oss-cn-guangzhou`）、`ossBucket`（桶名）、`accessKeyId` / `accessKeySecret`。AccessKey 用 **RAM 子账号**的，不要用主账号的。
2. **小程序**：在[微信公众平台](https://mp.weixin.qq.com/)的「开发 → 开发管理 → 开发设置 → 服务器域名」里，`request` 和 `uploadFile` 都填**自己的后端域名**（必须 https，并已备案），因为小程序上传的是后端，不是直接传 OSS。

## 二、公共读（小程序显示图片）

小程序的 `<image>` 标签如果直接用裸链接，Bucket 就必须是**公共读**。阿里云有两层限制，两层都要改对：

1. **创建时**：读写权限只能选「私有」，这是阿里云强制的，正常现象，直接创建；
2. **创建后**，进入 Bucket →「权限管理」：
   1. 先到「阻止公共访问」，把开关**关闭**；
   2. 再到「读写权限」，改成**公共读**。

只改第二步没用，「阻止公共访问」默认开着，会照样拦截访问，图片返回 403。

另外，小程序「服务器域名」里的 `downloadFile` 要加上 OSS 域名，不然下载、预览图片会被拦截。

## 三、浏览器直传（后台上传）

后台直传不能把长期密钥发给前端，要后端用 **STS** 换一个临时凭证，前端拿着临时凭证直接传给 OSS。在 [RAM 控制台](https://ram.console.aliyun.com/) 里：

1. 创建一个 RAM 子账号，生成 AccessKey；
2. 创建一个 RAM 角色，可信实体选**当前阿里云账号**；
3. 给角色添加权限 `AliyunOSSFullAccess`，给子账号添加权限 `AliyunSTSAssumeRoleAccess`；
4. 把角色的 **ARN** 填进后端配置。

我们踩过这个坑：ARN 一直是空的，后台上传就一直失败，排查了一阵才发现。

`AliyunOSSFullAccess` 是对所有 Bucket 的完全权限，范围比较大。想收紧的话，可以自定义一个只允许操作指定 Bucket 的权限策略，再挂给角色。

浏览器直传是跨域请求，还要给 Bucket 配 **CORS**。进入 Bucket →「权限管理」→「跨域设置（CORS）」，添加一条规则：

| 项目 | 填写 |
| --- | --- |
| 来源 | 后台的域名，比如 `https://admin.example.com` |
| 允许 Methods | GET、POST、PUT、DELETE、HEAD |
| 允许 Headers | `*` |
| 暴露 Headers | `ETag` |

## 四、图片处理（缩略图）

OSS 自带图片处理，在图片链接后面加参数就能按需裁剪、缩放，比如：

```
https://<bucket>.<region>.aliyuncs.com/pic/xxx.jpg?x-oss-process=image/auto-orient,1/resize,m_fill,w_200,h_200
```

后台的列表页、头像、素材预览都可以用它，不用自己再生成缩略图，也能省流量。

## 五、私有 Bucket（敏感文件）

公共读的 Bucket 里，任何人拿到链接就能访问，**不适合放证件照、支付证书、私钥这类敏感文件**。这类文件要单独建一个**私有** Bucket，创建时保持默认私有，不用动「阻止公共访问」。

私有 Bucket 的文件不能再用裸链接访问，读取时要么用 OSS SDK，要么生成**带有效期的签名 URL**。所以如果项目是先用一个公共读桶跑起来的，后面再拆分，代码里下载和显示的地方都要同步改。

## 建议：一个项目一个 Bucket

不同项目的文件不要混在同一个 Bucket 里：以后单独统计流量、控制权限、清理数据都更方便，也避免授权范围被不必要地放大。新建时先看清桶名，别误点进别的项目的 Bucket。

## 排查清单

- 图片返回 403：先看「阻止公共访问」是不是还开着，再看读写权限是不是公共读；
- 后台上传失败：看 ARN 是否填了，子账号是否挂了 `AliyunSTSAssumeRoleAccess`；
- 浏览器控制台报跨域：检查 CORS 的来源是否和后台域名完全一致，包括 `https://`；
- 小程序上传失败：检查 `request` 和 `uploadFile` 白名单里有没有后端域名；图片显示不出来：检查 `downloadFile` 里有没有 OSS 域名。

AccessKey 只放在后端配置里，不要写进代码、文档或聊天记录；一旦泄露，马上到 RAM 里轮换。
