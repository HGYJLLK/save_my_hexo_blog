小程序里用户要上传头像、图片，后台要管理素材，这些文件放哪里？最省心的做法是用阿里云的对象存储 **OSS**。这篇讲四件事：OSS 是什么、有什么优势、大概多少钱，以及以微信小程序为例怎么接入。

## 一、OSS 是什么

OSS（Object Storage Service）是阿里云提供的对象存储服务：你把图片、文件上传到一个叫 **Bucket**（存储桶）的地方，每个文件会得到一个访问地址，之后通过这个地址读取。可以把它理解成一个放在云上、不限容量、按用量付费的网盘，专门给程序用。

## 二、为什么用 OSS，而不是存在自己的服务器上

| 对比 | 存服务器本地磁盘 | 用 OSS |
| --- | --- | --- |
| 容量 | 受服务器磁盘限制，满了要扩容 | 不用管容量，用多少付多少 |
| 带宽 | 图片流量占用服务器带宽，访问多了拖慢接口 | 图片流量走 OSS，不占服务器带宽 |
| 上传 | 所有文件都要经过服务器 | 可以让浏览器直传 OSS，服务器不转发 |
| 缩略图 | 要自己写代码生成、存多份 | 链接后加参数即可按需裁剪缩放 |
| 迁移 | 换服务器要搬文件 | 文件在云上，服务器随便换 |
| 权限 | 要自己写 | 公共读、私有、签名链接、临时凭证都是现成的 |
| 费用 | 为用不满的磁盘和带宽付费 | 按存储量、流量、请求次数计费 |

对小程序来说最实用的是三条：**图片加载更快**（下面单独讲）、**图片流量不占自己服务器带宽**，以及**图片处理不用自己写代码**。

### 对小程序来说，OSS 还会更快

如果后端跑在家里的宽带上（比如家宽加 IPv6 转发、内网穿透），图片也跟着走这条线，用户打开小程序就会感觉慢，原因有几个：

- **家宽上行带宽小**：家庭宽带通常下行大、上行小，而用户看图片是从你这边「下载」，吃的正是你的上行带宽。图片一多、人一多，带宽就被占满；
- **线路不稳定**：用户到家宽要走运营商线路，跨运营商、跨地区时延迟和丢包都更明显，转发多一跳还会再慢一点；
- **图片拖累接口**：图片和接口共用同一条线，图片加载时，登录、下单这些接口也跟着变慢。

换成 OSS 之后，图片由阿里云机房出带宽，线路是多运营商的，和家里的网络无关。小程序里的**接口走后端，图片走 OSS**，两边互不影响，首屏加载图片的速度会明显改善。后端哪怕仍然在家里，也只需要处理接口请求，压力小很多。

这是原理上的判断，具体快多少取决于你的宽带和用户所在的地区，建议上线前用手机在不同网络下实测一次。

## 三、价格

OSS 默认是按量付费，主要有三项：存储、流量、请求。下面是阿里云官网定价页（中国内地地域，标准存储，按量付费）上的价格，我在 2026-10-03 查看，以官网实时价格为准：

| 计费项 | 价格 |
| --- | --- |
| 存储（本地冗余） | 0.12 元/GB/月 |
| 存储（同城冗余） | 0.15 元/GB/月 |
| 上传（流入）流量 | 免费 |
| 内网流出流量 | 免费 |
| 外网流出流量 | 闲时（00:00–08:00）0.25 元/GB，忙时（08:00–24:00）0.50 元/GB |
| CDN 回源流出流量 | 0.15 元/GB |
| PUT 类请求（上传） | 每月每地域前 500 万次免费，超出 0.01 元/万次 |
| GET 类请求（读取） | 每月每地域前 2000 万次免费，超出 0.01 元/万次 |
| 图片处理（缩放、裁剪等） | 每月前 10 TB 免费，超出 0.025 元/GB |

另外，阿里云还提供**资源包**（存储包、流量包），比按量付费更便宜，用量稳定后可以考虑买。

### 一个小程序大概要多少钱

假设一个刚上线的小程序：图片一共 10 GB，每月被下载 50 GB 流量，请求次数在免费额度内：

- 存储：10 GB × 0.12 = **1.2 元**
- 外网流出：50 GB 按最贵的忙时价 0.5 元算 = **25 元**（实际有一部分在闲时，会更少）
- 请求和图片处理：免费额度内，**0 元**

一个月最多约 **26 元**，而且这是按全部流量都按忙时价算的上限。用户量小的话，每月几块钱就够。

### 怎么省钱

- **流量是大头**：存储很便宜，花钱的主要是外网流出。把图片压缩后再上传，能直接省流量；
- **用图片处理参数输出小图**：列表页用缩略图，不要直接加载原图；
- **接 CDN**：流量大了以后，OSS 回源走 CDN 回源价 0.15 元/GB，比直接外网流出便宜。

## 四、以微信小程序为例：怎么接入

### 先搞清楚：小程序里的文件操作，和 OSS 的哪项能力对应

| 业务功能 | 用到的 OSS 能力 | 怎么配 |
| --- | --- | --- |
| 小程序里用户上传图片 | 服务端上传：小程序传给自己的后端，后端用 SDK 写进 Bucket | 后端配置 Bucket、地域和 RAM 子账号的 AccessKey；小程序域名白名单加后端域名 |
| 小程序里显示图片 | 公共读：图片用裸链接直接访问 | Bucket 设为公共读并关闭「阻止公共访问」；`downloadFile` 白名单加 OSS 域名 |
| 管理后台上传素材、图片 | 浏览器直传：用 STS 临时凭证，文件不经过自己的服务器 | RAM 角色加 STS 权限，后端提供换凭证接口；Bucket 配 CORS |
| 后台列表里显示缩略图 | 图片处理：链接后加 `x-oss-process` 参数 | 不用额外配置 |
| 存放证件照、证书这类敏感文件 | 私有 Bucket：读取时用签名链接 | 单独建一个私有 Bucket，代码里改成签名 URL 或用 SDK 读取 |

下面按顺序一步步来。

### 第 1 步：开通 OSS，创建 Bucket

在 [OSS 控制台](https://oss.console.aliyun.com/) 开通服务，创建 Bucket，地域选离用户近的（比如广州是 `oss-cn-guangzhou`）。

小程序的 `<image>` 标签如果直接用裸链接，图片桶就必须是**公共读**。阿里云有两层限制，两层都要改对：

1. **创建时**：读写权限只能选「私有」，这是阿里云强制的，正常现象，直接创建；
2. **创建后**，进入 Bucket →「权限管理」：
   1. 先到「阻止公共访问」，把开关**关闭**；
   2. 再到「读写权限」，改成**公共读**。

只改第二步没用，「阻止公共访问」默认开着，会照样拦截访问，图片返回 403。

一个项目建一个 Bucket，别和别的项目共用：统计流量、控制权限、清理数据都会更清楚。

### 第 2 步：创建 RAM 子账号，并分配权限

**为什么要子账号：** 阿里云主账号的 AccessKey 拥有所有权限，一旦泄露整个账号都有风险。所以要用主账号（或者有 `AliyunRAMFullAccess` 权限的 RAM 管理员）在 [RAM 控制台](https://ram.console.aliyun.com/) 里创建一个**只管 OSS 的子账号**，后端用它的 AccessKey。

#### 2.1 创建子账号

1. 登录 [RAM 控制台](https://ram.console.aliyun.com/)；
2. 左侧菜单：**身份管理 → 用户**，点「**创建用户**」；
3. 填写「登录名称」和「显示名称」（比如登录名 `oss-uploader`）；
4. 「访问方式」勾选「**使用永久 AccessKey 访问**」（也就是 OpenAPI 调用访问）。不需要登录控制台，就不要勾「控制台访问」；
5. 点确定，按提示完成手机验证；
6. 创建成功后会显示 **AccessKey ID** 和 **AccessKey Secret**。**Secret 只显示这一次**，马上下载 CSV 文件或复制保存，丢了只能重新生成。

#### 2.2 给子账号分配权限

在用户列表里找到刚创建的子账号，点「**添加权限**」（或「新增授权」），在权限策略里搜索下面的名字，选系统策略：

| 权限策略名称 | 作用 | 谁需要 |
| --- | --- | --- |
| `AliyunOSSFullAccess` | 管理 OSS，包括上传、读取、删除 | 后端用子账号的 AccessKey 直接把文件写进 Bucket（服务端上传） |
| `AliyunSTSAssumeRoleAccess` | 允许调用 STS 的 `AssumeRole`，换临时凭证 | 后端给管理后台发临时凭证（浏览器直传） |

两个都勾上，再点确定。

> `AliyunOSSFullAccess` 是对账号下**所有 Bucket** 的完全权限，范围偏大。想收紧，见下面「只授权单个 Bucket」。

#### 2.3 创建 RAM 角色（浏览器直传用）

浏览器直传要用到的临时凭证，是后端让子账号去「扮演」一个角色换来的，所以还要创建这个角色：

1. 左侧菜单：**身份管理 → 角色**，点「**创建角色**」；
2. 「可信实体类型」选「**云账号**」，「可信实体名称」选「**当前云账号**」；
3. 填写角色名称（比如 `oss-upload-role`），完成创建；
4. 在角色列表里点这个角色，给它**新增授权**：选系统策略 `AliyunOSSFullAccess`；
5. 进入角色详情，在基本信息里找到 **ARN**，点右侧的「复制」。它长这样：`acs:ram::<账号ID>:role/<角色名称>`。

这个 ARN 就是后端配置里的 `arn`。**ARN 为空，后台直传就一直失败**，我们就踩过这个坑。

#### 2.4 汇总：谁有什么权限

| 对象 | 权限策略 | 用途 |
| --- | --- | --- |
| RAM 子账号 | `AliyunOSSFullAccess` | 服务端上传（小程序传图） |
| RAM 子账号 | `AliyunSTSAssumeRoleAccess` | 向 STS 换临时凭证 |
| RAM 角色 | `AliyunOSSFullAccess` | 管理后台浏览器直传 |

后端配置里填：子账号的 `accessKeyId` / `accessKeySecret`，加上角色的 `arn`。

#### 2.5 进阶：只授权单个 Bucket

想让子账号和角色只能操作自己的 Bucket，不要用 `AliyunOSSFullAccess`，改成自定义策略：

1. 左侧菜单：**权限管理 → 权限策略**，点「**创建权限策略**」，选「脚本编辑」；
2. 粘贴下面的内容（把 `<bucket>` 换成桶名），保存并命名；
3. 回到子账号或角色，用「添加权限」选「自定义策略」，把它加上。

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject", "oss:GetObject", "oss:DeleteObject"],
      "Resource": ["acs:oss:*:*:<bucket>/*"]
    }
  ]
}
```

### 第 3 步：服务端上传（小程序传图）

小程序里用 `uni.uploadFile`（或 `wx.uploadFile`）把图片传给自己的后端，后端再用 `ali-oss` 的 SDK 写进 Bucket，把返回的 https 地址存起来。文件名用随机 ID，再加一个前缀目录（比如 `avatar/`、`order/`），方便分类和以后清理。

后端需要配置：`region`（地域）、`bucket`（桶名）、`accessKeyId` / `accessKeySecret`。

小程序要在[微信公众平台](https://mp.weixin.qq.com/)的「开发 → 开发管理 → 开发设置 → 服务器域名」里配置：

- `request` 和 `uploadFile` 合法域名：填**自己的后端域名**（必须 https，并已备案），因为小程序上传的是后端，不是直接传 OSS；
- `downloadFile` 合法域名：填 **OSS 域名**，用于下载、预览图片。

### 第 4 步：浏览器直传（后台上传）

管理后台上传文件，可以让浏览器直接传给 OSS，文件不经过自己的服务器。但不能把长期密钥发给前端，要用 **STS 临时凭证**：后端用 AccessKey 调用 STS 的 `assumeRole`，换一个有效期很短的临时凭证给前端。

需要的子账号权限、角色和 ARN，都在上面的**第 2 步**里创建好了。后端调用 STS 的 `assumeRole`，传入角色的 ARN，就能拿到临时凭证（有效期很短）交给前端。

直传是浏览器跨域请求，还要给 Bucket 配 **CORS**。进入 Bucket →「权限管理」→「跨域设置（CORS）」，添加一条规则：

| 项目 | 填写 |
| --- | --- |
| 来源 | 后台的域名，比如 `https://admin.example.com` |
| 允许 Methods | GET、POST、PUT、DELETE、HEAD |
| 允许 Headers | `*` |
| 暴露 Headers | `ETag` |

### 第 5 步：图片处理（缩略图）

OSS 自带图片处理，在图片链接后面加参数就能按需裁剪、缩放，比如：

```
https://<bucket>.<region>.aliyuncs.com/avatar/xxx.jpg?x-oss-process=image/auto-orient,1/resize,m_fill,w_200,h_200
```

列表页、头像、素材预览都可以用，不用自己再生成缩略图，也省流量。按前面的价格表，每月前 10 TB 的图片处理是免费的。

### 第 6 步：敏感文件用私有 Bucket

公共读的 Bucket 里，任何人拿到链接就能访问，**不适合放证件照、支付证书、私钥这类敏感文件**。这类文件要单独建一个**私有** Bucket，创建时保持默认私有，不用动「阻止公共访问」。

私有 Bucket 的文件不能再用裸链接访问，读取时要么用 OSS SDK，要么生成**带有效期的签名 URL**。所以如果先用一个公共读桶跑起来，后面再拆分，代码里下载和显示的地方都要同步改。建议一开始就分开。

## 排查清单

- 图片返回 403：先看「阻止公共访问」是不是还开着，再看读写权限是不是公共读；
- 后台上传失败：看 ARN 是否填了，子账号是否有 `AliyunSTSAssumeRoleAccess`，角色是否有 OSS 权限；
- 服务端上传失败：看子账号是否有 `AliyunOSSFullAccess`（或自定义的 OSS 权限）；
- 浏览器控制台报跨域：检查 CORS 的来源是否和后台域名完全一致，包括 `https://`；
- 小程序上传失败：检查 `request` 和 `uploadFile` 白名单里有没有后端域名；图片显示不出来：检查 `downloadFile` 里有没有 OSS 域名。

AccessKey 只放在后端配置里，不要写进代码、文档或聊天记录；一旦泄露，马上到 RAM 里轮换。
